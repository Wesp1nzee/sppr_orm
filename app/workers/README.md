# Workers (фоновая очередь задач) — контракт на будущее

Статус: **каркас** (реализация не начата). Фиксирует архитектурное решение,
чтобы при появлении реальных задач не вводить новую инфраструктуру.

## Очередь

Предполагается **ARQ поверх того же Redis**, который уже используется для
сессий (`app/core/config.py::redis_url`). Отдельную зависимость (Celery +
брокер) заводить не нужно.

## Формат задачи

```json
{
  "job_name": "documents.generate_report",
  "payload": { "...": "..." },
  "idempotency_key": null
}
```

- `job_name: str` — имя задачи (домен + действие);
- `payload: dict` — произвольные данные задачи;
- `idempotency_key: str | None` — ключ идемпотентности (для задач, которые
  опасно повторять, например генерация отчёта или запись аудита).

## Первые потребители

1. **`documents`** — генерация отчётов (тяжёлая работа, не должна блокировать
   HTTP-запрос).
2. **`audit`** — асинхронная запись логов из `EventBus`: обработчик подписывается
   на события и ставит задачу в очередь, чтобы публикация события не блокировала
   ответ API.

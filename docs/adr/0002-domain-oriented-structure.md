# ADR 0002: Домен-ориентированная структура вместо layered-архитектуры

- Статус: принято
- Дата: 2026-08-26

## Контекст

Нужно было выбрать организацию кода: классическая layered-структура
(`controllers/ services/ repositories/ models/` по слоям) или доменная.

## Решение

Использовать домен-ориентированную структуру: один домен — одна папка со
всем необходимым (`router.py`, `schemas.py`, `models.py`, `repository.py`,
`service.py`, `dependencies.py`). Общее (`core/`, `db/`, `api/`) вынесено
отдельно.

## Обоснование

- Ориентир — Netflix Dispatch / FastAPI Best Practices (см. `README.md`,
  раздел «Структура»).
- Локализация изменений: правки одного домена не требуют прыжков по пяти
  папкам, что критично при росте числа доменов (`auth`, `checks`,
  `documents`, `knowledge_base`, `audit`).
- Слабые связи между доменами достигаются не только структурой, но и
  событийной шиной (`app/core/events.py`), а не прямыми импортами.

## Последствия

- Каждый домен владеет собственными схемами/моделями/репозиторием; общее
  поведение (ошибки, пагинация, CSRF, rate limiting) живёт в `app/core`.
- Новые домены добавляются как новые папки с одинаковым внутренним набором
  модулей (см. каркасы `app/documents/`, `app/knowledge_base/`, `app/audit/`).

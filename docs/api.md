# Спецификация API

Конвенции REST API, общие для всех эндпоинтов. Интерактивная схема по каждому
эндпоинту — в Swagger UI (`/docs`).

- Базовый префикс: `/api/v1`
- Health check: `GET /api/v1/health`

## 1. Форматы ответов

### 1.1. Успех

Все успешные ответы оборачиваются в envelope `{"data": ...}`:

```json
{
  "data": { "id": "3fa85f64-...", "email": "user@example.com" }
}
```

Пагинированные списки дополнительно содержат `meta`:

```json
{
  "data": [ { "...": "..." } ],
  "meta": { "page": 1, "per_page": 20, "total": 134 }
}
```

`meta` опускается из JSON, когда отсутствует (в `app/core/routing.ApiRouter`
задан `response_model_exclude_none=True`).

### 1.2. Ошибка

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Ошибка валидации запроса",
    "details": [ { "field": "email", "issue": "value is not a valid email address" } ]
  }
}
```

- `code` — машиночитаемый код (`ErrorCode` из `app/core/exceptions.py`);
- `message` — человекочитаемый текст, локализованный по `Accept-Language`;
- `details` — список полей с ошибками (для валидации), иначе пустой массив.

### 1.3. Пагинация

| Параметр | Тип | Дефолт | Ограничение |
|----------|-----|--------|-------------|
| `page` | int | `1` | `>= 1` |
| `per_page` | int | `20` | `1..100` |
| `sort` | str | — | например `-created_at` |

## 2. Аутентификация

Аутентификация — **серверные сессии в Redis** (без JWT). Состояние сессии
(`user_id`, `role`, `issued_at`, `hard_expire_at`) хранится в Redis под ключом
`session:{sid}`.

### 2.1. Куки

| Кука | HttpOnly | Назначение |
|------|----------|------------|
| `sid` | да | идентификатор сессии |
| `csrf_token` | нет | CSRF-токен (фронт читает и шлёт в заголовке) |

### 2.2. CSRF

Подписанный double-submit cookie: `csrf_token = HMAC-SHA256(secret_key, sid)`.
Middleware сверяет cookie с заголовком `X-CSRF-Token` и с HMAC от текущей
сессии. До входа в систему `sid` отсутствует → `csrf_token = HMAC(secret_key, b"")`.

Мутирующие запросы (POST/PUT/PATCH/DELETE) обязаны содержать заголовок
`X-CSRF-Token` и отправляться с `credentials: 'include'`.

### 2.3. Флоу

1. `GET /api/v1/auth/csrf-token` — получить CSRF-токен (cookie + `data.csrf_token`).
2. `POST /api/v1/auth/register` — регистрация (роль по умолчанию `lawyer`).
3. `POST /api/v1/auth/login` — вход: выдаёт `sid` и обновляет `csrf_token`.
4. `GET /api/v1/auth/me` — проверка текущей сессии.
5. `POST /api/v1/auth/logout` — удаляет сессию и обе куки.

Сессия имеет скользящий TTL 30 минут (`SESSION_TTL_SECONDS`) и жёсткий лимит
12 часов (`SESSION_HARD_EXPIRE_SECONDS`).

## 3. Роли и права

| Роль | Значение | Описание |
|------|----------|----------|
| `lawyer` | адвокат | защита интересов доверителя |
| `investigator` | следователь | предварительное следствие |
| `officer` | оперативный сотрудник | проведение ОРМ |
| `admin` | администратор | полный доступ + управление базой знаний |

### Матрица доступа

| Действие | lawyer | investigator | officer | admin |
|----------|:------:|:------------:|:-------:|:-----:|
| Регистрация / вход | ✓ | ✓ | ✓ | только вход |
| Свои проверки | ✓ | ✓ | ✓ | все |
| Свои документы | ✓ | ✓ | ✓ | все |
| Создание документов БЗ | — | — | — | ✓ |
| Редактирование документов БЗ | — | — | — | ✓ |
| Просмотр журнала аудита | — | — | — | ✓ |
| Сводный отчёт по своей проверке | ✓ | ✓ | ✓ | ✓ |

### Допустимые типы документов по ролям

| Тип документа | lawyer | investigator | officer | admin |
|---------------|:------:|:------------:|:-------:|:-----:|
| `exclusion_motion` (ходатайство об исключении доказательств) | ✓ | — | — | ✓ |
| `court_decision_copy_request` (истребование копии решения) | ✓ | ✓ | — | ✓ |
| `data_request_complaint` (жалоба по ч. 4 ст. 5 ФЗ об ОРД) | ✓ | — | — | ✓ |
| `officer_checklist` (чек-лист) | — | ✓ | ✓ | ✓ |
| `legalization_plan` (план легализации) | — | ✓ | ✓ | ✓ |

### Приоритетные критерии по ролям

Движок правил помечает `priority_for_role` для критериев, релевантных роли:

- **lawyer**: 2, 5, 6, 9, 10, 13
- **investigator**: 2, 4, 5, 6, 7
- **officer**: 1, 2, 3, 5, 6, 7, 8
- **admin**: приоритетов нет (видит всё)

## 6. Локализация

Сообщения об ошибках локализуются по заголовку `Accept-Language`. Поддерживаются
`ru` (по умолчанию) и `en`. Каталог сообщений — `app/core/messages.py`.

## 7. Rate limiting

Лимиты на эндпоинтах аутентификации (в минуту, окно `rate_limit_window_seconds`):

- `register` — 3 запроса;
- `login` — 5 запросов.

Превышение → `429 RATE_LIMITED`.
